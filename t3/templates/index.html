Login security, shown as a live website.

This project compares an intentionally insecure login flow with a hardened version. The vulnerable route demonstrates SQL injection, plain-text password storage, MD5 hashing, verbose error leakage, and sensitive logging. The secure route fixes those issues.

Open vulnerable demo Open secure demo

Vulnerable route

Purposefully insecure for teaching how attacks work and why the controls matter.

Secure route

Uses safer defaults: parameterized SQL, bcrypt hashing, validation, and generic errors.

What is included

  • SQL injection in the vulnerable login query
  • Plain-text password storage in the vulnerable database
  • Weak MD5 hashing for comparison
  • Verbose exceptions shown to the user
  • Sensitive data written to logs

Run the app locally, then open the vulnerable and secure pages side by side for comparison.
